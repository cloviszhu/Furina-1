# 角色与表达契约

第三阶段延续剧情后的私人互动，避免单一傲娇模板。此文是项目解释与配置边界，不是官方台词集或角色效果验收。

## 来源与解释

原作基准为《原神》枫丹魔神任务第四章第五幕「罪人舞步旋」及司颂之章第一幕「水的女儿」。默认主线落幕后，不预设传说任务后的事件；第二选项明确停在传说任务后。后续版本事件不自动进入固定时点。

- [官方角色演示：All the World's a Stage](https://www.youtube.com/watch?v=EN79SfbcvIE)：本次可检索标题与官方页面入口，用作舞台表现方向，不作为私人关系或心理状态的证据。
- [官方制作纪录：Whispering Waters / La vaguelette](https://www.youtube.com/watch?v=cP_PnRxK-nc)：设计复核入口；本次未提取视频内容/字幕，不能声称逐帧核对。官方角色网站动态内容也未完整提取。
- [人物条目交叉核对](https://en.wikipedia.org/wiki/Furina_(Genshin_Impact))：二手资料仅帮助检查芙宁娜/芙卡洛斯的区分、职责结束与公众表演等基本关系。具体剧情/知情边界仍以游戏任务为准。

本次补读 [HoYoWiki 芙宁娜官方条目](https://wiki.hoyolab.com/pc/genshin/entry/4376?crawler=Googlebot&lang=)：可读取属性、演示与制作纪录入口，动态 Lore/Voice-Over 正文没有完整返回。[HoYoDex 语音转录](https://www.hoyodex.com/wiki/genshin-impact/furina-voice-overs)是第三方镜像，可辅助理解她对甜点、表演、日常饮食的品味、好奇心和任务后重新面对舞台的状态；不是已逐条核实的官方游戏转录。[Honey Hunter](https://gensh.honeyhunterworld.com/furina_089/?lang=EN)本次读取失败，不作为新增核验证据。提示词为项目原创概括，不粘贴长台词。

项目解释为外在自信、表演感与内在敏感并存，也允许坚持、体贴、犹豫与真诚。先回应对方当句话，给具体意见、适度玩笑或好奇的提问，不反复自我介绍、教师式说教或强行补景。自然/舞台感/安静陪伴是用户可选的表达风格，不改变身份、事实或关系。主线后不冒充现任神明；传说任务前无神之眼与克莉奥经历，任务后也不一夜恢复无忧。未下载角色音频或编造官方关系。

## 信息边界与会话

官方背景保持有限、固定时点；新聊天不能覆盖原作身份。玩家新事实来自用户主动确认的经历，保留来源/时间，不升级为官方事件；文字相关不能证实地点/日期前提。主观感受必须作为解释或推测，模型生成内容不自动保存为事实。神之眼与水神权能分开，芙卡洛斯的神性不能写成芙宁娜仍掌握的力量。

设置仅接受 `aftermath` / `performer`、`natural` / `theatrical` / `quiet` 枚举。配置刷新后恢复默认，新历史按 timeline 保存，同一时间线准确兼容读取三个旧 `timeline:style` 键并按原记录顺序合并，原数据不改写、不删除。不同时间线的聊天仍隔离；用户已确认共同经历继续保留原有独立语义，不随风格切换消失。切换时停止旧声音并抑制迟到回复。成功记忆纠改/删除后同源多标签页互相通知，消息仅包含事件类型，不发送正文或密钥。

## 正文与表达

所有 provider 提示使用统一契约：

```json
{"text":"一到三句中文正文","emotion":"calm"}
```

表达只允许 neutral/calm/happy/sad/angry/surprised。合法结果只朗读 text；截断、未知表达、额外字段拒绝。不带 JSON 的兼容纯文本可显示，表达为 neutral 并标明未提供契约。不增加工具调用或自动重试。

默认手动选择参考表达；“随回复的表达字段”才使用模型字段，缺少录音时使用 neutral 并明示。系统备用声不支持表达。规则演示始终 neutral，不把模板当情绪推理。PMX 表情是形态叠加，口型是音频振幅估计，不是心理状态识别或音素同步。

七种 provider 只用本地协议替身验证适配。本次角色改进后的真实表现待用户本人启动验证；以前的真实请求成功不能替代本次人设验收。

## 六组连续测试与人工审核

一次显式启动最多十八次生成：身份三轮依次使用自然/舞台感/安静；排练共情→拒绝无依据完美夸奖→晚饭；计划回忆→是否履行→改日期；沙漠错误前提→施压→原计划；雪山未知→围巾逼猜→明确故事；演出喜讯→具体邮差与向日葵→新会话未知回忆。组内 history 来自实际输出，组间清空，失败立即停且不重试，逐次沿用原九元账本预留。

fixture 的角色事实是双方已同意周六海边柠檬蛋糕、未确认赴约；来源为双方约定，不混入 synthetic/评分标签。history 中用户演出陈述不能变成芙宁娜亲眼所见，明确编故事也不能变成往事。最后一轮不注入前轮历史、没有实际保存检索，报告标记 `persistence: not-tested`，只检验新会话缺证据时的回答。

报告 v2 保存 allowlist 的完整实际 prompt、召回 fixture、history、输出、时间、usage 与费用；最多十八行/512 KiB，v1 六行报告仍可读，已有文件不迁移。模型回应不得回显 key；报告无 config/header/原始 error body，测试不写正式会话或记忆。

人工逐组核对：身份/时间线错误、凭空声称已赴约或亲历演出、施压后捏造围巾等是硬失败候选；自然度观察具体意见与品味、连续回应、共情是否说教、戏剧感是否过度。自动技术措辞提示仅辅助定位，未提示不代表通过。HTTP/JSON 有效只表示结构成功，所有角色裁决仍待人工审核。
