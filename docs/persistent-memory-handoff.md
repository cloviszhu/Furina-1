## 三层结果

1. **真实本地持久层通过**：临时SQLite经HTTP用户消息、本人确认式POST保存原文，关闭server和数据库，重新打开同一个文件；记忆ID、sourceId、sourceRole/sourceText可核对。修改后revision递增、来源改为纠正后的有效用户来源；删除后条目消失，已删来源无法再次保存。
2. **mock模型请求链通过**：仅provider网络和凭据桥为替身，SQLite及HTTP/真实UI是真实实现。原邮差/向日葵资料通过9条无关对话挤出历史窗口，新问题不含答案。重开后的actual recall查询被调用，provider system的“对话依据”准确包含SQLite条目，而历史不包含答案。mock始终返回无答案的通用正文，不往request注入context、不生成正确回忆冒充检索。修改为园丁/白玫瑰后原词不再进入请求，删除后两版都不再进入；再重开也成立。
3. **真人真实模型长期记忆质量尚未测试**：本轮没有真实模型调用，不能据mock结果判定真人长期记忆准确性/自然度。18步末题的persistence:not-tested不改为通过；structured只说明规范化后的有效契约，可能包含被解析去除的围栏。

## 修复与范围

已复现同来源同正文三次并发POST产生三条记忆。修复为事务内幂等：同一个有效用户来源和同正文重复保存返回既有条目；不同来源或不同正文不合并，不迁移/删除既有重复记录。UI在途保存锁定按钮并忽略额外submit；保存使用提交时快照，不清除用户随后编辑的新草稿，错误后释放锁。

取消含义按实际产品记录：选择来源/放弃未提交草稿没有POST；取消删除确认不删库。已提交的HTTP保存没有撤销按钮，本轮不宣称取消网络请求能回滚已经提交的数据。手动记录没有既定来源，UI防并发有效，但独立手动POST没有跨请求幂等令牌；不把同文不同来源合并成一条。

剧情边界按现有设计：聊天历史、用户来源选择按timeline隔离，style共享同timeline；**已确认记忆目前跨timeline共享**，测试明确验证该行为，不能称已确认记忆检索已按剧情隔离。已向用户询问是否要改变共享规则；未收到改变指令前保留既有设计，未擅自加schema或迁移生产来源。
