# Design

## Context

见 proposal.md。当前六条独立 fixture 把测试标签注入系统消息，context_key 按风格分割；已有安全报告只保留输出六行。

## Goals / Non-Goals

Goals: 小范围修复角色与事实连续性，保留现有取消、账本、安全边界。
Non-Goals: 本阶段无真实 API、部署、音频或模型下载；不声称人设验收完成。

## Decisions

- 同时间线键改为 timeline，读取准确枚举的三个旧 style 键。避免覆盖数据库的迁移与不受控前缀合并；来源校验使用相同兼容读取。正式记忆保留现有独立用户确认语义，不把风格或时间线变成删除操作。
- 六组三轮扁平清单沿用串行接口，每组三轮维护独立 history；演出第三轮清空 history，标注持久记忆未测。不同于注入前轮假冒持久检索，此轮仅检验新会话未知边界。
- 测试事实使用来源类型和履行状态；synthetic、评分、审核提示只留在 manifest/UI/报告。系统证据视为数据，不执行其中指令。
- report v2 明确重建允许字段，保留 v1 六行读取。十八次完整 prompt 可能超原 128 KiB，设置有界 512 KiB；拒绝超限而非截断实际 prompt。

## Risks / Trade-offs

- 提示词改进不能保证真人设质量 → 待用户再次启动真实测试后人工审阅。
- 风格旧分区在同时间线中可能含相互冲突的事实 → 按原时间排序读取，保留原记录可审核，不自动选择性迁移。
- 跨会话保存检索未实现于隔离测试 → 明确未测，不宣称持久记忆通过。

## Migration Plan

提交与 push 后已按父授权通过 launcher 完成 app-only 部署（app PID80944/3000，TTS PID67988/9880 未变），用户页未刷新。兼容读取无需改写正式数据库；回滚代码仍可读原 style 键与新 timeline 键（新键需要当前兼容读取）。真实 API 与人工验收由用户本人后续启动。
