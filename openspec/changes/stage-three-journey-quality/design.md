# Design

## Context

见 proposal.md。现有 Node/SQLite、Three PMX、单 GPU TTS 已可运行；独立 QA commit 已合入。模型服务目前仅规则演示，真实 LLM 与角色声线尚待用户材料/凭证。

## Goals / Non-Goals

**Goals:** 在现有模块边界补齐角色参数、正文/表达契约、语音一致性及故障恢复证据。

**Non-Goals:** 不重写舞台，不下载权重，不训练，不访问凭证，不以替身证明人格成长/情绪理解或声音相似度。

## Decisions

1. 角色配置采用有限枚举（主线落幕后/重返舞台、自然/戏剧/安静），默认延续原配置。配置作为每次聊天参数，UI 切换隔离旧页内历史；后端历史按角色配置标识筛选，避免时点混合，不删除既有记录。共同经历仍为用户确认的记录，非官方事实。
2. 模型提示请求紧凑 JSON `{text,emotion}`，所有协议统一解析和验证，不强加供应商不支持的 response_format。纯文本兼容为 neutral，非法 JSON 拒绝。对 key 回显和 usage 扩展字段过滤，防止恶意替身通过响应回传凭证。
3. 声音设置提供手动与随回复表达两种模式，默认手动；自动模式只使用已登记 emotion，缺失回落 neutral 并明示。改设置立即 stop，新回复使用完成时的当前选项。
4. 表情使用已有 PMX morph 温和叠加，保留振幅口型和眨眼；没有该 morph 时无操作。用实际截图与顶点/形态测试验证，不安装物理或动作资源。
5. 保留 loopback、预算预留、无自动重试；测试数据隔离到临时目录，真实生产旅程仅使用有标识且清理的验收记录。只重启核实的项目进程。
6. 同源多标签页使用不含文字/秘密的记忆修改通知，成功纠改/删除后使其他页停止已显示的旧上下文、旧语音及来源；失败的修改不广播。后端 generation 继续负责待返回请求，通知不取代服务端边界。

## Risks / Trade-offs

- [128 token 可能截断 JSON] → 非法结构拒绝并标注演示回退，不提高费用上限。
- [官方网页提取不完整] → 记录可核查官方链接与证据可读范围，设计解释不冒充官方原话。
- [参考表情不等于心理状态] → UI 标记模型字段/手动选择，声音自然度仍待人工。
- [GPU 不支持硬取消] → 只停止投递，已有串行队列继续约束下一任务。

## Migration Plan

SQLite 新增带默认值的会话配置列，旧事件维持默认配置。构建后仅重启应用进程，TTS 不重复启动。回退普通 revert，资产/数据/预算不清空。
