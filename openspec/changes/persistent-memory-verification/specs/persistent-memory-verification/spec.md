## Purpose
建立从用户确认保存、持久数据库重开、真实检索结果进入模型请求的可验证链路，保持来源ID、修改和删除的语义完整，防止重复保存，并严格区分本地持久层验证与真实模型长期记忆质量验收。

## ADDED Requirements
### Requirement: 持久检索与来源
系统 SHALL 将本人确认的合成经历保存到SQLite，重开后实际检索进入请求；来源必须是现存用户事件，assistant或不存在的事件不得保存为来源。
#### Scenario: 重开与新请求
- **WHEN** 保存邮差/向日葵经历并移出历史窗口、关闭重开server和DB
- **THEN** 不含答案的新问题仍经实际检索把记忆放入provider请求，mock正文不提供答案。
#### Scenario: 修改删除
- **WHEN** 修改或删除已保存资料后重开
- **THEN** 新请求不含旧资料，来源ID对应当前有效源。

### Requirement: 确认与重复保存
系统 SHALL 只在提交确认后保存，相同来源和正文重复请求幂等；在途保存期间UI不得再次提交。
#### Scenario: 取消和重复
- **WHEN** 用户放弃未提交草稿或重复提交同一来源正文
- **THEN** 草稿不写库，重复不新增记忆。

### Requirement: 验证层级
交付 MUST 区分持久层验证、mock请求组装和真人真实模型尚未验证，不升级persistence:not-tested批次题为通过。
#### Scenario: mock回归报告
- **WHEN** 本地链路通过
- **THEN** 报告仍指出真人真实聊天加保存重开检索未执行。
